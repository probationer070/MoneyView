## 1. 오너 결정(2026-10-19, 시안으로 고름)

| # | 내용 |
|---|---|
| U-D1 | `/` 맨 위에 얇은 **신호 줄**이 늘 있다. 평소에는 조용한 줄이고, 신호가 있으면 같은 자리가 배너가 된다. 줄을 누르면 언제든 패널이 열린다(시안 A). |
| U-D2 | 패널을 닫아도 다시 열 수 있다. 지난 기록도 볼 수 있어야 한다(오너: "나중에 다시 열 수 있도록 하면서 이전에 있던 기록들도 추가로 열람"). |

| U-D4 | 기록은 요약어만 보이지 않는다. 테마별·종목별 상세 숫자를 남기고 보인다(오너: "7개 테마, % 적중이라고 하면 모르니까 … 각각의 상세 정보"). "적중" 같은 말 대신 실제 값과 기준을 적는다. |
| U-D5 | 패널 탭은 **급락 / 위험 후보 / 급등 / 어제 상승** 네 개다. |
| U-D6 | 표나 보고서 형태로 볼 수 있어야 한다(오너: "필요한 경우 보고서나 표의 형태로"). |

상위 스펙 R-D3~R-D6과 R-D14는 그대로 지킨다. 덱 모양은 카드가 겹쳐 보이는 형태이고, 방향키로 넘기며, 카드를 누르면 상세 화면으로 간다.

## 2. 신호 줄(`/` 맨 위)

- **자리.** 시장 개요 헤더 위다. 높이는 한 줄이고, 시장 개요는 그만큼 줄어든다. `/`는 1280×720과 390×844에서 계속 페이지 스크롤이 없어야 한다.
  - **기존 검사는 완화하지 않는다(내 판단).** 오너가 승인한 `market-one-screen` 검사는 "모든 카드와 스프레드가 패널 스크롤 없이 들어간다"를 확인한다.
  - 줄 때문에 카드가 넘치면 시장 개요 쪽 여백을 줄여 맞춘다. 헤더와 탭 사이 간격, 카드 안쪽 여백 같은 것이고, 토큰 안에서 줄인다.
  - 그래도 안 되면 신호 줄을 헤더 행 안(지역 문장 옆)으로 넣는다. 검사를 느슨하게 하는 것은 마지막 수단이고, 그때는 오너에게 묻는다.
  - **390 폭에서는 한 줄을 유지하고 넘치는 글자는 말줄임표로 줄인다.** 줄을 늘리지 않는다.
  - 상위 스펙 §3.3의 "경보가 없을 때 `/`는 지금과 똑같다"는 이 결정(U-D1)으로 바뀐다. 줄이 늘 있기 때문이다.
- **상태와 내용.** 우선순위가 위에서 아래다.

| 상태 | 내용 | 색 |
|---|---|---|
| 위험 경보 진행 중 | "위험 신호가 잡혔습니다" · 경보 테마 수와 주요 테마 이름 · 시작일 · 켜진 경계 지표 "4/6" | 하락 방향(`--down` 계열 surface와 ink) |
| 급등 배너(위험 경보 없음) | "강한 상승이 확인되었습니다" · 사건 중인 테마 이름 · 시작일 | 상승 방향(`--up` 계열) |
| 평소 | 경계 지표 "2/6" · 어제 상승 1위 종목과 등락률 · 사건 중인 급등 테마 수 | 기본 줄(`--surface-raised`, `--line`) |
| 평가 전·과거 계산 중 | "신호 계산 중" 또는 "데이터 준비 중" 한 줄 | 기본 줄 |

  - **색은 시장 관례를 따른다(내 판단).** 한국 시장 관례에 따라 하락이 파랑, 상승이 빨강이다(DESIGN.md). 위험 경보는 하락 신호라 하락 색을 쓰고, 급등은 상승 색을 쓴다. 새 토큰은 만들지 않는다.
  - **위험 경보와 급등 배너가 같은 날 있으면** 위험 경보가 줄을 차지한다. 급등은 줄 끝에 작은 표시 하나("급등 2")로만 보인다.
- **누르면 패널이 열린다.** 줄 전체가 버튼이다. 키보드로는 Enter와 Space로 연다.
- **문구는 매매 권유로 읽히지 않게 쓴다.** "팔아라", "사라", "오를 것" 같은 말을 쓰지 않는다(상위 스펙 범위 밖, ②-b §11).

## 3. 신호 패널(시장 개요 위에 덮는 창)

### 3.1 배치

- **1280 폭.**
  - 왼쪽에 카드 덱이 있고, 덱 아래에 탭 네 개가 있다.
  - 오른쪽에 뉴스 목록이 있다.
  - 맨 아래에 "기록 보기 ›" 링크가 있다.
- **390 폭.** 위에 덱과 탭, 아래에 뉴스를 쌓는다.
- **스크롤.** 패널이 열린 상태에서도 페이지 스크롤은 없다. 뉴스 목록은 패널 안에서 스크롤된다.
- **열고 닫기.**
  - 열기: 신호 줄을 누른다.
  - 닫기: 닫기 버튼, Esc, 패널 바깥 누르기.
  - 주소는 바뀌지 않는다(R-D14).
- **자동 펼치기.** 새 위험 경보 id와 새 급등 배너(배너가 켜진 날의 첫 사건 id)를 처음 볼 때 한 번 자동으로 펼친다. 본 id는 브라우저 로컬 저장소에 적고, 읽지 못하면 매번 펼친다(상위 스펙 §3.1). 어제 상승은 자동으로 펼치지 않는다.

### 3.2 탭과 카드

| 탭 | 데이터 | 카드 내용 |
|---|---|---|
| 급락 N | `/latest.alert.crash`. 경보가 없으면 `/latest.last_alert`의 기록을 보이고, 그 사실과 날짜를 탭 안에 밝힌다(R-D8). | 종목·이름·테마, 20일 고점 대비 하락률, 고점일, 30일 종가 선, 헤드라인 0~2개 |
| 위험 후보 N | `alert.candidates`, 없으면 마지막 경보의 기록 | 종목·이름·테마, 63일 고점과의 차이, 상관 상대와 상관값("SOX와 0.85") |
| 급등 N | `/latest.surge.themes`. 배너가 꺼져 있어도 사건 중인 테마 전부다. | 테마 이름, 시작일, 요소 값 네 개(크기 z, 기울기 분위, 폭 %, RSI), 과열 표시, 시작일의 주도 종목 5개 |
| 어제 상승 5 | `/latest.movers` | 순위, 종목·이름·테마, 하루 등락률, 5일 등락률, RSI. 아래에 "예측이 아닌 어제의 결과입니다" 한 줄을 둔다. |

- **덱 동작은 상위 스펙 §3.2와 같다.**
  - 앞 카드 뒤로 다음 카드가 살짝 보인다.
  - 넘기는 방법은 마우스 드래그, ←/→, 이전·다음 버튼이다.
  - 위치를 "3 / 10"처럼 보인다.
  - Enter를 누르거나 카드를 누르면 종목 카드는 `/detail/[ticker]`로 간다.
  - 급등 카드는 테마 카드라서 누르면 그 사건의 기록 화면(§4의 상세)으로 간다.
  - 넘기는 움직임은 모션 시스템을 쓰고, 동작 줄이기 설정에서는 바로 바뀐다.
- **10장 제한(R-D6).** 급락과 위험 후보는 앞 10장과 마지막 "전체 N개 보기" 카드를 보인다. "전체 N개 보기"를 누르면 기록 페이지의 그 경보 상세로 간다.
- **비어 있는 탭.** 탭은 늘 보인다. 비면 "지금은 해당 종목이 없습니다" 같은 빈 상태를 보인다.

### 3.3 뉴스

- 위험 경보가 있으면 `/latest.alert.news`를 보인다. 거시 뉴스가 먼저이고, 한국어와 영어가 섞인다. 거시 주제 옆에는 `macro_figures`의 수치를 함께 보인다(예: "9월 CPI +0.65% m/m (8월 +0.40%)").
  - `news_shortfall` > 0이면 "N개 부족"을 보인다.
  - `news_note`가 있으면 사유를 보인다. `before_collection`은 "수집 이전 경보", `feed_failed`는 "최근 수집 실패"다.
- 위험 경보가 없으면 뉴스 칸에 경계 지표 6개 표를 보인다. 칸은 지표 이름, 상태, 값, 관측일, 기준 문장(`rule`)이다.
  - 경보 화면의 뉴스는 기록 상세(§4)에서 본다.
  - 경보가 없을 때 뉴스 칸을 따로 채우는 API는 없다. 새 API를 만들지 않는다(내 판단).

## 4. 기록 페이지 `/alerts`(새 화면)

- **주소.** `/alerts`이고, 상세는 `/alerts/[kind]/[id]`다. `kind`는 `risk`, `surge`, `movers`다. `movers`의 id는 날짜(`YYYY-MM-DD`)다.
- **데이터 범위(내 판단).** 표는 한 번에 가져와 화면에서 거른다. 각각 다음을 한 번 부른다.
  - `/history?limit=500`
  - `/surge/history?limit=500`
  - `/movers?from=2016-01-04`(최대 2,600거래일, 약 13,000행)

  지금 기록은 경보 11건, 급등 약 220건이라 충분하다. 범위 인자는 더하지 않는다.
- **색.** 상위 스펙 §3.3의 "위험·경고 의미 토큰"은 이 문서의 방향 색(§2)으로 바꾼다. `status.error`가 상승 빨강이라 위험 경보에 쓰면 뜻이 뒤집히기 때문이다(내 판단).
- **기존 경로와의 구분.** 기존 `/signals`(시나리오 엔진)와 헷갈리지 않게 따로 둔다(내 판단).
- **한 화면.** `ONE_SCREEN_ROUTES`에 더한다. 1280×720에서 페이지 스크롤이 없고, 표와 상세는 각자 안에서 스크롤된다.
- **위쪽.** 거르기 줄이 있다. 종류는 전체 / 위험 / 급등 / 어제 상승이다. 기간은 시작~끝 날짜다. 배너에 보인 것만 거르는 선택은 급등에만 있다. 오른쪽에는 "CSV 내려받기" 버튼이 있다.
- **왼쪽 표.** 행 하나가 신호 하나다.

| 종류 | 표의 칸 |
|---|---|
| 위험 | 시작일, 해제일, 일수, 테마 수와 앞 3개 이름, 켜진 지표, 주 테마의 5·10·20일 등락, "10일 안 최대 추가 하락"과 기준 −5% 대비 |
| 급등 | 테마, 시작일, 끝난 날·끝난 이유, 배너 표시, 5·10·20일 등락, "10일 안 최대 추가 상승" |
| 어제 상승 | 날짜, 1~5위 종목과 등락률(한 행이 하루) |

  - "과거 데이터로 계산" 기록에는 작은 표시를 단다(② `origin: backfill`).
- **오른쪽 상세.** 행을 누르면 오른쪽에 보고서가 나온다. 주소도 `/alerts/[kind]/[id]`로 바뀌어서 바로 열 수 있다.
  - **위험 경보 보고서**
    1. 머리말: 시작일~해제일, 계산 기준 버전, 과거 계산 표시
    2. 켜진 경계 지표와 실제 값(시작일)
    3. 테마별 표: 들어온 날·경로, 들어온 날 20일 고점 대비, 5·10·20일 뒤, 10일 안 최대 추가 하락, 빠진 날
    4. 요약 문장(예: "7개 중 1개가 10일 안에 5% 넘게 더 빠짐 — 광통신 −7.4%"). 테마별 값에서 만들며 "적중"이라는 말은 쓰지 않는다(U-D4).
    5. 시작일 카드 스냅샷: 급락과 위험 후보, 각 종목의 그 뒤 5·10·20일
    6. 뉴스와 거시 수치
  - **급등 사건 보고서**
    1. 머리말
    2. 시작일 요소 값 네 개와 기준 문장(`surge_rule_text`)
    3. 과열이 된 날
    4. 그 뒤 5·10·20일과 10일 안 최대 추가 상승
    5. 주도 종목 5개
    6. 끝난 이유
  - **어제 상승 하루:** 다섯 종목 표다.
- **차트(내 판단).** 위험·급등 보고서 위에 주 테마 지수 선 하나를 둔다. 신호 구간은 음영이다.
  - 이 차트를 위해 API를 하나 더한다: `GET /api/v1/risk/themes/{theme}/level?from=&to=`. 날짜별 지수 값을 낸다(§6).
  - 차트가 화면 높이를 넘기면 빼고 표만 둔다. 한 화면 규칙이 우선이다.
- **CSV.** 지금 걸러진 표를 내려받는다. 화면에서 만들고, 서버 API를 새로 만들지 않는다.
  - 칸 이름은 화면 언어를 따른다.
  - 숫자는 반올림하지 않은 API 값이다.

## 5. 위쪽 메뉴와 연결

- 왼쪽(또는 위쪽) 메뉴에 "신호 기록"(`/alerts`)을 더한다.
- 패널의 "기록 보기 ›"는 `/alerts`로 가고, 지금 경보가 있으면 그 상세로 간다.

## 6. API 추가(작게)

- `GET /api/v1/risk/themes/{theme}/level?from=&to=`
  - 낸다: `[{date, level}]`. 테마 지수를 시작 100으로 맞춘 값이다.
  - `^SOX`는 종가를 같은 방식으로 맞춘다.
  - 기간은 최대 400거래일이다.
  - 없는 테마는 404 `unknown_theme:<id>`다.
- 지수는 저장하지 않았으므로 요청할 때 계산한다. DB 일봉을 읽어 `theme_indices`로 만든다. 400일 범위라 가볍다.
- `packages/shared-types/risk.ts`에 타입을 더한다.

**빌더 검토 뒤 더하는 칸과 옵션(내 판단).** 화면이 보여야 하는데 기존 응답에 없던 값이다.

| 무엇 | 어디에 | 내용 |
|---|---|---|
| 전체 카드 | `GET /alerts/{id}?cards=all` | `crash`와 `candidates`의 카드를 10장 제한 없이 낸다. 기본값은 지금처럼 10장이다. "전체 N개 보기"와 기록 보고서가 쓴다. |
| 급등 주도 종목 | `/latest.surge.themes[].leaders` | `[{ticker, name, return5_pct}]`. 사건에 저장된 값이다. |
| 급등 기준 문장 | `/latest.surge.components_info`, `/surge/events/{id}.components_info` | 요소 네 개의 `{id, label{ko,en}, rule{ko,en}}`. `rules.yaml`의 `surge_labels`와 `surge_rule_text`에서 온다. |
| 급등 배너 시작 | `/latest.surge.banner_since` | 배너가 지금 이어서 켜져 있는 구간의 첫 날이다. `risk_daily.surge_banner`에서 구한다. 배너가 꺼져 있으면 null이다. 자동 펼치기는 이 날짜를 키로 쓴다. |
| 기록 목록의 상세 칸 | `RiskAlertSummary.max_dd10`, `trigger_labels` | 주 테마의 10일 안 최대 추가 하락과 테마 이름(`{ko,en}`)이다. 행마다 상세를 다시 부르지 않는다. |

- **테마 이름이 없는 카드.** 카드의 `theme`은 id다. 화면은 ①의 `GET /api/v1/portfolio/watchlist/themes`로 이름을 바꾼다. `^SOX`는 API의 SOX 이름을 쓴다.
- **마지막 경보로 대신 보일 때.** 경보가 없을 때 급락·위험 후보 탭은 `/alerts/{last_alert.id}`를 한 번 더 부른다. 의도한 동작이다.
- 그 밖의 값은 기존 API로 충분하다.
  - `/latest`
  - `/history`, `/alerts/{id}`
  - `/surge/history`, `/surge/events/{id}`
  - `/movers`

## 7. 지켜야 할 것

- **디자인 토큰만 쓴다(CLAUDE.md §10, DESIGN.md).**
  - 숫자는 mono 스타일이다.
  - 등락은 ▲/▼와 +/−를 붙인다.
  - `npm run lint`와 `design:baseline`을 통과해야 한다.
- **문구는 ko/en 카탈로그(`apps/web/lib/i18n/messages`)에 둔다.**
  - JSX에 문자열을 직접 쓰지 않는다.
  - 한국어는 용어집(`docs/design/MoneyView_Glossary.md`)을 따른다.
- **모션은 공용 부품을 쓴다.** `Tabs`, `mv-enter`, `RollingNumber`다. 동작 줄이기 설정을 지킨다.
- **접근성.**
  - 신호 줄은 버튼이다.
  - 패널은 대화상자 역할을 하고, 초점을 가두고, Esc로 닫는다.
  - 덱은 방향키로 넘기고 지금 위치를 읽어 준다.
  - 탭은 `Tabs` 부품을 쓴다.
- **데이터가 없을 때.**
  - `/latest`의 `as_of`가 null, `backfill`이 running/degraded/failed, `surge`·`movers`가 null인 경우를 모두 자연스럽게 보인다.
  - 오류는 기존 `ErrorState`로 보인다.

## 8. 테스트

- **Playwright**(한 번에 하나, 3101/8110 포트가 비었을 때만). API 응답은 기존 e2e 목업 방식으로 고정한다.
  - **신호 줄:** 네 상태(평소, 위험, 급등, 둘 다)의 문구와 색 클래스
  - **패널:** 열기와 닫기(누르기, Esc, 바깥), 경보 id별 자동 펼침이 한 번만 일어나는지, 저장소가 막혔을 때 매번 펼치는지
  - **덱:** ←/→, 이전·다음, "3 / 10", 카드 → `/detail/[ticker]`, "전체 N개 보기"
  - **탭 네 개의 빈 상태**
  - **`/alerts`:** 거르기, 행 → 상세와 주소 변경, 직접 주소로 열기, CSV 내려받기 내용
  - **스크롤:** `/`와 `/alerts`가 1280×720과 390×844에서 스크롤이 없는지(패널 열린 상태 포함). 기존 `one-screen-no-scroll`, `market-one-screen` 검사가 계속 통과해야 한다.
  - **모션:** 동작 줄이기 기본값에서 통과해야 한다. 모션 확인은 해당 파일에서만 켠다.
- **pytest:** `themes/{theme}/level` 경로의 모든 경우를 확인한다.
- **변이 검사.** 모든 새 테스트는 변이 검사를 한다(CLAUDE.md §8).
