# 기업분석 한 화면 재구성 설계 (A: 화면·상세 모달)

Oct 14, 2026 · 브레인스토밍 결과. 오너 승인 섹션 1~4.

## 배경과 목표

`/corporate`는 1280px 폭에서 높이 약 2,800px(스크롤 4화면)이다. 검색·DCF·종목 추가 폼, 가정 슬라이더 세로 열, KPI·차트 3개, DCF 핵심값, 종목 비교(설명 문단·컨트롤·동기화 상태·빈 상태 박스)가 한 줄로 쌓여 있다. 셸의 좌우 여백 `lg:px-20`(80px)이 본문을 좁히고, 사이드바 하단(언어 토글·푸터)은 메뉴 바로 밑에 떠 있다. (캡처에서 사이드바가 중간에 끊겨 보이는 것은 full-page 스크린샷이 `fixed` 요소를 한 번만 그리기 때문이며, 실제 화면 높이 문제는 아니다.)

완료 상태:

- 1280×720에서 스크롤 없이 **"이 종목이 싼가/비싼가"** 에 답한다: 판정, 핵심 KPI 4개, 가정 표가 첫 화면 안에 있다.
- 나머지(진단 차트, DCF, 종목 비교)는 첫 화면 하단의 탭 3개로, 각 탭은 한 화면 높이 안에 들어간다.
- 설명 문단은 ⓘ 툴팁이나 상세 모달로 옮기고, 화면에서 지운 정보는 없다(이동만 한다).
- 상세 모달(`CalculationDetailModal`)은 내부 탭 6개로 정리되고, 추이·동종업 위치·가정 민감도가 추가된다.

범위 밖:

- 백엔드·API·계산 로직 변경(A는 프론트엔드만). 판정 라벨 규칙도 바꾸지 않는다.
- **B: 동종업 비교군 데이터**(미국 동종업 상위 10~20개 기업, 규모·수익률). 별도 스펙·계획으로 A 이후 진행한다. A의 모달은 B가 들어올 자리를 갖춘다.

## 1. 셸(모든 페이지): 좌측 사이드바 → 상단 고정 바 (D9)

좌측 256px 세로 사이드바는 공간 낭비가 커서 없앤다. 대신 상단 고정 가로 바를 둔다.

```
┌■ MoneyView │ ▦ ◔ ≡ [▣ 기업분석] ◎ ✎ ⚖ ✦ □ │ EN|한 ┐   ← 48px, 항상 보임
│            ┌──────────────────────┐              │
│ (hover)    │ ▦ 시장 개요  Market    │              │   ← 바 아래로 펼쳐지는
│            │ ◔ 포트폴리오 Portfolio │              │      수직 메뉴 패널
│            │▌▣ 기업분석  Corporate │              │
│            │ …                     │              │
│            │ Powered by FastAPI…   │              │
│            └──────────────────────┘              │
```

- **바(접힌 상태):** `fixed top-0 inset-x-0`, 높이 48px(`h-12`), `z-40`, 하단 1px hairline. 왼쪽 로고, 가운데 메뉴, 오른쪽 언어 토글(`LanguageToggle`).
  - 메뉴 항목은 아이콘만 보이고, **현재 페이지 항목만** 아이콘 + 짧은 라벨(기업분석 등)을 보인다. 아이콘 항목은 `aria-label`과 `title`에 전체 이름을 가진다.
  - 각 항목은 그대로 링크다(바에서 바로 이동 가능).
- **펼친 상태:** 바에 마우스를 올리거나(hover), 키보드 포커스가 바 안으로 들어오거나(`:focus-within`), 바의 ☰ 버튼을 누르면 바 바로 아래에 수직 메뉴 패널이 펼쳐진다.
  - 패널은 기존 사이드바의 내용(아이콘 + 전체 이름, 현재 페이지 브랜드 막대, 하단 "Powered by" 푸터)을 그대로 가진다.
  - 본문을 밀어내지 않고 위에 겹친다(overlay). 배경 스크림 없음.
  - 닫힘: 마우스가 바·패널 영역을 벗어나고 150ms 뒤, Escape, 패널 밖 클릭, 페이지 이동.
  - ☰ 버튼은 `aria-expanded`/`aria-controls`를 가진다. 터치 기기는 hover가 없으므로 ☰ 탭으로 연다.
- **좁은 화면(<768px):** 바에는 로고 · 현재 페이지 이름 · ☰ · 언어 토글만. 메뉴는 ☰로만 연다. 기존 모바일 슬라이드 사이드바와 스크림은 없어진다.
- **본문:** `AppShell`의 `<main>`에서 `lg:ml-64`를 없애고, 위쪽 여백은 바 높이 + 16px(`pt-16`), 좌우 여백은 `lg:px-8`. 1280px에서 본문 폭이 약 860px → 약 1,216px.
- `Sidebar.tsx`는 `TopNav.tsx`로 대체된다(메뉴 항목 정의는 공유). 메뉴 항목 목록·순서·경로·아이콘은 지금과 같다.
- 모든 페이지 배치가 바뀌므로 디자인 시스템 캡처(`design-capture`)를 새로 찍고, 사이드바를 단언하는 기존 테스트(`sidebar-contrast.spec.ts` 등)는 기존 테스트 변경 목록에 넣어 승인받는다.

## 2. 첫 화면 (1280×720, 스크롤 없음)

```
┌─ 기업분석 CORPORATE ── [AAPL ▾ 검색] ── 갱신 13:02 [↻ DCF] ┐
│ Apple · Technology · $231.40                          │
├──────────────────────────────────┬─────────────────────┤
│ 판정 VERDICT                     │ 가정 ASSUMPTIONS ⋯  │
│ 내재가치 $268  vs  현재가 $231   │ 성장률   6.0% OK  ✎ │
│ ▲ +15.9%   [저평가 Undervalued]  │ ROIC    18.0% OK  ✎ │
├────────┬────────┬────────┬─────────┤ WACC    10.0% 추정 ✎│
│ROIC−   │ Ke     │ WACC   │ 레버리지 │ …                   │
│WACC 8.0│ 10.0%  │ 10.0%  │ 베타 1.22│                     │
├────────┴────────┴────────┴─────────┴─────────────────────┤
│ [진단 차트] [DCF] [종목 비교]                           │
└────────────────────────────────────────────────────────┘
```

### 2.1 헤더 행

- 제목(`PageHeader`, eyebrow `corporate`), 종목 검색(`TickerSearch`), 마지막 갱신 시각, [↻ DCF] 버튼.
- 아래 한 줄: 회사명 · 섹터 · 현재가.
- 별도 "Add Company" 폼(회사명·심볼·Add for Analysis)은 없앤다. 검색 결과가 없을 때 드롭다운 마지막 항목 "목록에 없음 → 추가"가 같은 `POST /corporate/companies`를 호출하는 작은 인라인 폼(이름·심볼)을 연다.
- "Intrinsic DCF" 타일과 "DCF stays idle…" 안내 문장은 판정 블록(2.2)이 대신한다.

### 2.2 판정 블록 (좌측 2/3 상단)

- 값: `intrinsic_value_per_share` vs `current_price`, 상승여력 `upside_pct`.
- 상승여력은 `DeltaBadge`와 같은 규칙(▲/▼ 글리프 + 상승/하락 색 + 부호)으로 보인다.
- 라벨은 DCF 응답 `status`를 번역만 해서 보인다: `Undervalued` → 저평가 Undervalued, `Overvalued` → 고평가 Overvalued, `Bridge Incomplete` → 주당가치 산출 불가 Per-share value unavailable. 그 밖의 값은 받은 문자열을 그대로 보인다. 프론트엔드가 임계값을 새로 만들지 않는다.
- `Bridge Incomplete`이면 내재가치 자리에 `MISSING`(—)과 기업가치(EV)를 작게 보인다.
- DCF가 아직 계산되지 않았으면 N/A 대신 "DCF 미계산 · [↻ DCF]" 상태를 보인다(첫 로드 idle 원칙 유지).
- 블록 제목 ⓘ → 상세 모달 `backendDcf`.

### 2.3 KPI 4개 (좌측 2/3 하단)

ROIC−WACC, Bottom-up Ke, WACC, 레버리지 베타. 각 타일은 `KPIBlock`, 설명은 한 줄로 줄이고 제목 클릭 → 해당 상세 모달(`spread`, `bottomUpKe`, `wacc`, `leveredBeta`).

### 2.4 가정 표 (우측 1/3)

- 지금 `CorporateAssumptionsPanel`이 보이는 가정 행 전부를 행 하나씩: 항목명 · 값 · 상태 배지(OK/추정) · ✎ · ⓘ.
- ✎를 누르면 그 행 아래에 기존 `RangeControl` 슬라이더가 펼쳐진다. 한 번에 한 행만 펼친다(다른 행 ✎ → 이전 행 접힘). 값 변경 후 재계산 동작은 지금과 같다.
- ⓘ → 해당 상세 모달.
- 표 헤더의 ⋯ 메뉴: 원천 데이터 새로고침, ROIC 기준(최근 다년 평균 등) 선택, 성장 기준 표시.
- 지금의 주황색 블록 두 개(원천 데이터 상태, Country Risk Premium)는 일반 행과 한 줄 상태 문구로 줄인다.
- 표는 첫 화면 높이 안에 들어가야 하며, 넘치면 표 자체가 내부 스크롤한다(페이지 스크롤 아님).

## 3. 하단 탭 3개

공통: `Tabs` 컴포넌트, 선택 탭은 `useTabState("corporate.lowerTab", "diagnostics")`로 기억. 각 탭 내용은 약 420px 높이 안에 들어간다. 설명 문단은 탭 제목 옆 ⓘ 툴팁.

### 3.1 진단 차트

- Hurdle Rate 분해, 베타·WACC U-커브, 4분면 가치동인 매트릭스를 한 줄 3열(각 약 300×260px).
- 차트 제목·막대 클릭 → 상세 모달(지금과 같은 키).
- 992px 미만 2열, 768px 미만 1열.

### 3.2 DCF

- 좌: DCF 핵심값 4개(지속가능 성장, 터미널 가치 비중, FCFF 규모, 내재가치) — 지금 `DcfCoreModulesGraph` 데이터.
- 우: 5×5 민감도표(WACC × 영구성장률, 기존 `DcfSensitivityTable`). 전체 리포트가 로드된 뒤 보이고, 그 전에는 [리포트 불러오기] 버튼(`POST /corporate/dcf/{t}/report`, 기존 로드 함수 재사용).
- 원시 행·CSV는 모달에 남는다.

### 3.3 종목 비교

- 툴바 한 줄: 유니버스 · 벤치마크 · 정렬 · 방향 | [비교 새로고침] [전체 DCF 계산] [관심종목 동기화 확인].
- 상태 한 줄: "관심종목 n/m 동기화 · 벤치마크 ^GSPC · 마지막 계산 시각".
- 표(`CorporateComparisonTable`)는 남은 높이를 채우고 자체 세로 스크롤.

## 4. 상세 모달 (`CalculationDetailModal`)

모달 유지(`ModalShell` xl, 1080px). 헤더에 지표명 · 값 · 티커 고정. 기존 13개 섹션을 내부 탭 6개로 나눈다. 마지막으로 연 탭을 기억해(`useTabState("corporate.detailTab", "summary")`), 다른 지표를 열어도 같은 탭으로 열린다. 그 지표에 해당 탭이 없으면 요약 탭.

| 탭 | 내용 | 데이터 |
|---|---|---|
| 요약 | 큰 값 + 상태 + 의미 한 줄. 공식에 **실제 숫자를 대입한 식**(예: `WACC = 0.82×10.0% + 0.18×4.1%×(1−21%) = 8.8%`). 주요 입력 표: 값 · 출처 · 기준일 | `buildCalculationDetails` |
| 계산 과정 | 지금의 감사(Step 1..N), 데이터 리니지, 근거 행 | 기존 |
| 추이 | 2021→현재 연도별 선 차트 + 연도 표. 연간 값이 있는 지표만(성장률, ROIC, 부채비율, 재투자율, 베타, 혁신지수); 그 외 지표는 탭을 숨긴다 | `/corporate/metrics/{t}/history`. 미로드 시 [원천 데이터 불러오기] 버튼, 자동 요청 없음 |
| 동종업 비교 | A: 비교 계산이 끝났을 때만, 현재 비교 유니버스 안에서 이 지표의 순위와 분포 띠(최저–최고, 이 종목 위치). 비교 전이면 "종목 비교 탭에서 비교를 계산하면 보입니다". B 이후 동종업 10~20개 표로 교체 | 기존 비교 결과 |
| 민감도 | DCF 입력 가정만(아래 표). [계산] 누르면 현재값 −Δ, +Δ로 DCF 2회 호출, 내재가치·상승여력 변화를 보인다. 비대상 가정은 "DCF에 직접 쓰이지 않는 가정" 문구 | 기존 `POST /corporate/dcf/{t}`, 요청 시에만 |
| 원천 데이터 | OHLCV, 분기 재무제표, 전체 DCF 리포트(5×5 포함), CSV 내보내기 | 기존 |

### 4.1 민감도 Δ (오너 검토 대상)

슬라이더 step(0.25~1)은 결과가 거의 안 움직이므로 별도의 고정 Δ를 쓴다. 결과값은 슬라이더 min/max로 자른다(잘렸으면 표시).

| 가정 | DCF 요청 필드 | Δ |
|---|---|---|
| 성장률 | `revenue_growth_rate` | ±1.0%p |
| ROIC | `operating_margin` | ±2.0%p |
| WACC | `wacc` | ±1.0%p |
| 재투자율 | `reinvestment` | ±10%p |
| 비레버리지 베타 | `unlevered_beta` | ±0.10 |
| 부채비율 | `debt_ratio` | ±10%p |
| ESG/대리인 페널티 | `esg_penalty` | ±10점 |

요청 본문은 `dcfRequestBody(snapshot)`에서 해당 필드만 바꾼 것. 다른 필드는 현재 스냅샷 그대로.

## 5. 다국어

새 문구(판정 라벨, 탭 이름, 상태 줄, 버튼, 모달 탭, 민감도 문구)는 모두 `en`/`ko` 카탈로그에 넣고, 작은 라벨(eyebrow, 표 머리)은 항상 2개 언어(`BilingualLabel`). 용어는 `docs/design/MoneyView_Glossary.md`에 추가.

## 6. 오류·빈 상태

- 각 탭·모달 탭은 자기 요청의 로딩/오류/빈 상태를 따로 가진다(`EmptyState`, `ErrorState`). 한 탭의 실패가 첫 화면을 비우지 않는다.
- 민감도 두 호출 중 하나만 실패하면 성공한 쪽만 보이고 실패한 쪽은 오류 문구.
- DCF 거절(`DcfRefusalError`)은 판정 블록에 지금과 같은 문구로.

## 7. 테스트

새 e2e(`tests/e2e/corporate-one-screen.spec.ts`, `corporate-detail-tabs.spec.ts`). 각각 CLAUDE.md §8에 따라 깨뜨리는 변형으로 실패를 확인한다.

1. 1280×720: 헤더, 판정, KPI 4개, 가정 표의 bounding box가 모두 y < 720, 탭 바 상단도 720 안. `document.scrollingElement.scrollHeight`가 아니라 요소 위치로 판정.
2. 판정 라벨: `status` 3가지(Undervalued/Overvalued/Bridge Incomplete)와 미지의 값 하나를 모킹해 각 문구, ▲/▼, `data-dir`.
3. DCF 미계산 상태: "DCF 미계산"이 보이고 "N/A"가 없다.
4. 가정 ✎: 한 행만 펼쳐지고, 슬라이더 변경이 기존처럼 재계산 요청을 보낸다.
5. 하단 탭 기억: 탭 변경 → 다른 페이지 → 복귀 시 같은 탭.
6. 상단 바: 1280×720에서 바 높이 48px·`top: 0`, 본문 첫 요소가 바 아래(겹치지 않음), 스크롤해도 바 위치 고정. hover → 패널 보임, 벗어나면 닫힘; Tab 포커스로 열림; ☰ 클릭 토글과 `aria-expanded`; Escape·페이지 이동 시 닫힘; 현재 페이지 항목만 라벨 표시; <768px에서 ☰로만 열림.
7. 모달 6탭: 탭 전환, 추이 탭은 비연간 지표(예: `crp`)에서 숨김, 마지막 탭 기억.
8. 민감도: [계산] 시 `POST /corporate/dcf/{t}` 정확히 2회, 본문의 해당 필드가 현재값 ±Δ, 나머지 필드 동일. 한 호출 실패 시 부분 표시.
9. 추이 탭: 히스토리 미로드 시 자동 요청이 없다(네트워크 기록으로 확인).

**기존 테스트:** 버튼·설명 문구·위치가 바뀌어 기존 corporate e2e 상당수가 깨진다. 계획서에 깨지는 단언을 모두(파일:줄, 이전 → 이후) 나열하고, **수정 전에 오너 승인**을 받는다. 계산·API 테스트는 건드리지 않는다.

## 8. 순서와 다른 계획과의 관계

- 디자인 시스템 계획 Task 10(Portfolio) 다음, Task 11 전에 이 계획을 실행한다. 새 토큰·컴포넌트 위에서 바로 만든다.

## 9. 위험

- 첫 화면 높이 예산이 빠듯하다(헤더 ~96px, 판정 ~120px, KPI ~110px, 탭 바 ~44px, 여백 포함 약 400px + 가정 표 우측). 가정 행이 많아 표가 넘치면 내부 스크롤로 처리하며, 테스트 1이 회귀를 잡는다.
- 상단 바 전환은 모든 페이지 배치에 영향(본문 폭 약 +350px). 캡처 리뷰로 확인. 넓어진 폭에서 기존 페이지의 표·차트가 늘어나 보일 수 있으며, 그 조정은 각 화면의 디자인 시스템 태스크(9~13)에서 한다.
- hover 메뉴는 의도치 않게 열리기 쉽다. 150ms 닫힘 지연만 두고, 열림 지연은 두지 않는다. 겹치는 패널이 본문 클릭을 막지 않도록 닫힌 상태에서는 `pointer-events: none` + `hidden`.
- `page.tsx`(1,242줄)가 더 커지지 않도록 첫 화면 블록(판정, KPI 행, 가정 표)과 하단 탭을 각각 컴포넌트 파일로 나눈다.
