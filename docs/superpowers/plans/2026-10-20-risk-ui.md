# Risk and Surge Signal Screens Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build three things:
- the always-on signal strip on `/`
- the overlay signal panel, with crash / candidates / surge / yesterday's-gainers decks and news
- the `/alerts` records page, with per-theme reports and CSV export

Also add the small API fields the screens need.

**Architecture:**
- Backend first: the API additions from spec §6, then the TS types.
- The web side uses one client data hook module, `apps/web/lib/useRisk.ts`, with react-query in the same pattern as `useSignals.ts`.
- Components live in `apps/web/components/risk/`:
  - `SignalStrip`
  - `SignalPanel`
  - `CardDeck` (generic)
  - the card renderers
  - `NewsColumn`, `WarningsTable`
  - `RecordsTable`, `RecordReport`, `ThemeLevelChart`
- New route `app/alerts/[[...slug]]/page.tsx`.
- Copy lives in `lib/i18n/messages/{ko,en}.ts`.
- Playwright mocks go in `tests/e2e/helpers/riskApiMock.ts`.

**Tech Stack:** Next.js app router, React, TypeScript, Tailwind with design tokens, @tanstack/react-query, Playwright; FastAPI and pytest for the API additions.

**Spec:** `docs/superpowers/specs/2026-10-20-risk-ui-design.md`. It builds on the API in `2026-10-19-risk-engine-design.md` §6 and `2026-10-19-surge-signal-design.md` §8.

### Task 1: API additions and TS types

**Files:** `apps/api/routes/risk.py`, `apps/api/models/schema_parts/risk.py`, `apps/api/services/risk/store.py` (only if a query helper is needed), `packages/shared-types/risk.ts`, `tests/api/risk/test_routes.py`.

**Interfaces** (spec §6, "빌더 검토 뒤 더하는 칸"):
- `GET /alerts/{id}?cards=all`
  - Default (no `cards`): cards stay at 10, as today.
  - `cards=all`: every stored card.
  - Any other value: 422.
- `/latest.surge.themes[].leaders: [{ticker, name, return5_pct}]`, from the stored event.
- `components_info: [{id, label{ko,en}, rule{ko,en}}]`
  - Appears on `/latest.surge` and on `/surge/events/{id}`.
  - The order is magnitude, accel, breadth, rsi.
  - Values come from the rules `surge_labels` and `surge_rule_text`.
- `/latest.surge.banner_since: YYYY-MM-DD | null`
  - It is the first day of the current unbroken run of `risk_daily.surge_banner = 1`, ending at the latest evaluated day.
  - It is null when the latest day's banner is off.
  - Only days of the current rules version count, and backfill gating applies.
- `RiskAlertSummary.max_dd10: float | null`: the primary theme's first-stint `max_dd10`.
- `RiskAlertSummary.trigger_labels: [{id, label{ko,en}}]`: same order as `trigger_themes`.
- `GET /themes/{theme}/level?from=&to=`
  - Returns `[{date, level}]`, rebased to 100 at the first returned day.
  - The theme comes from the theme list or is `^SOX`. `^SOX` uses its closes.
  - The default window is the last 120 trading days. The maximum is 400 trading days; a longer request gets 422 `range_too_long`.
  - An unknown theme gets 404 `unknown_theme:<id>`.
  - The level is computed with `theme_indices` from DB closes and current shares, read once per request.

**Interfaces:**
- **Panel shell.** The panel uses `ModalShell` (focus trap and Esc), or an overlay with the same behaviour. Clicking outside closes it, and the URL does not change.

    - `news_shortfall` shown as "N개 부족";
    - `news_note` text.
  - Otherwise it shows `WarningsTable`, the six warnings from `/latest.warnings` (name, state, value, observed_at, rule).

### Task 5: `/alerts` page: route, filters, table, CSV

**Files:**
- Create: `apps/web/app/alerts/[[...slug]]/page.tsx`, `apps/web/components/risk/RecordsTable.tsx`, `apps/web/lib/recordsCsv.ts`, `apps/web/tests/e2e/risk-records.spec.ts`
- Modify: `components/ui/oneScreenRoutes.ts` (add `/alerts`), `components/ui/navItems.ts` (add "신호 기록"), the i18n catalogs

**Interfaces:**
- **Slug parsing.** `[]` is the list view. `[kind, id]` with `kind` in `risk`, `surge` or `movers` selects a record. Anything else is the not-found state.
- **Filters.**
  - Kind: all / risk / surge / movers.
  - Date range: from and to.
  - A "배너에 보인 것만" toggle, shown only for surge.
  - Filter state lives in the URL query, so it survives a reload.
- **Table.** Columns per spec §4. Rows from the previous rules-version backfill are not shown. A backfill origin carries a "과거 데이터로 계산" badge. Clicking a row routes to `/alerts/<kind>/<id>`, keeping the query.
- **Data loading.** Load once, then filter on the client (spec §4):
  - `/history?limit=500`
  - `/surge/history?limit=500`
  - `/movers?from=2016-01-04`
- **CSV.** `recordsCsv(rows, kind, locale) -> string`.
  - Headers follow the UI language.
  - Numbers are unrounded API values.
  - Quoting follows RFC 4180.
  - Download is a Blob link, file name `moneyview-signals-<kind>-<from>_<to>.csv`.
